   - Background workers for queue processing, wearable sync, KB growth

   - Password hashing: bcrypt with 12 rounds, 72-byte truncation handled
   - JWT authentication with proper token creation/validation

   - SQL injection protection via SQLAlchemy ORM

3. ERROR HANDLING & OBSERVABILITY

   - Structured JSON logging with request duration tracking
   - Graceful degradation (ML model falls back to rule-based prediction)

4. FEATURE COMPLETENESS
   - 20+ medical features: Voice AI, wearables, predictive ML, knowledge graph
   - Multi-platform: Web PWA, Android/iOS (Capacitor), Desktop (Electron)
   - Hybrid AI service with auto-fallback chain
   - RAG pipeline with FAISS vector search

================================================================================
                         CRITICAL ISSUES
================================================================================

1. SECURITY VULNERABILITIES
--------------------------------------------------------------------------------

   [HIGH] Default SECRET_KEY in Development (config.py:30)
   -------------------------------------------------------
   Issue: The fallback generates a new key on each restart, invalidating all
          sessions. Production check exists but is bypassable.

   Fix: Require SECRET_KEY in development too, or use a stable default with
        clear warning.

   [MEDIUM] Password Reset Token Exposure (auth_new.py:493-496)
   ------------------------------------------------------------
   Issue: Tokens returned in API response instead of email. Commented "Remove
          this in production" but still in code.

   Code:
       return {
           "message": "...",
           "reset_token": reset_token,  # SECURITY RISK!
           "reset_link": reset_link
       }

   Fix: Remove token from response, integrate email service (SendGrid/SES).

   [MEDIUM] OAuth State Parameter Not Validated (auth_new.py:267-268)
   ------------------------------------------------------------------
   Issue: CSRF protection incomplete - state is generated but not validated
          on callback.

   Fix: Store state in session/cache, validate on callback.

   [LOW] CORS Allow-All Origins in Dev (config.py:36-39)
   -----------------------------------------------------
   Issue: Multiple localhost origins including port 3000. Not dangerous in
          dev but should be stricter.

2. CODE QUALITY ISSUES
--------------------------------------------------------------------------------

   [HIGH] TODOs in Production Code (20 occurrences found)
   ------------------------------------------------------
   Locations:
   - main.py:2 - "TODO: Replace stub logic"
   - voice.py:242 - Hardcoded user ID: created_by_id=1
   - readmission_predictor.py:179 - "TODO: Calculate actual confidence"
   - config.py:108-113 - Multiple validation TODOs

   Impact: Indicates incomplete implementation, technical debt accumulation.

   Fix: Address all TODOs or convert to tracked GitHub issues.

   [MEDIUM] Silent Exception Handling (auth_new.py:28-29)
   ------------------------------------------------------
   Code:
       except Exception as e:
           logger.warning(f"Failed to load .env file: {e}")
           pass  # Silent failure!

   Impact: Could lead to missing critical configuration without warning.

   Fix: Fail fast on critical config errors, or use explicit defaults.

   [MEDIUM] Magic Numbers in ML Model (readmission_predictor.py:207-227)
   ---------------------------------------------------------------------
   Code:
       score = 0.1  # Base risk
       score += previous_readmissions * 0.25
       score += min(comorbidity_count * 0.1, 0.3)

   Impact: No documentation for coefficient selection. Not reproducible.

   Fix: Extract to named constants with citations to medical literature.

   [MEDIUM] Database Connection Per Request (main.py:122-189)
   ----------------------------------------------------------
   Issue: Creates new DB connection every 5-minute wearable sync iteration.

   Fix: Reuse connection or use connection pool properly.

--------------------------------------------------------------------------------

3. ARCHITECTURAL CONCERNS
--------------------------------------------------------------------------------

   [HIGH] Monolithic main.py (1096 lines)
   --------------------------------------
   Single file contains:
   - Lifespan management (startup/shutdown)
   - Background workers (queue, wearable, KB growth - 3 separate loops)
   - Health check endpoints
   - Medical diagnosis endpoints
   - Knowledge base endpoints
   - Prescription endpoints
   - Upload handling
   - Request/response middleware

   Impact: Difficult to test, maintain, and extend. High coupling.

   Fix: Split into:
   - lifespan.py - Startup/shutdown logic
   - workers.py - Background task loops
   - health.py - Health check endpoints
   - Keep only router registration in main.py

   [MEDIUM] Circular Import Risk (main.py:40-55)
   ---------------------------------------------
   Issue: All API routers imported at module level (15+ imports).

   Impact: As codebase grows, circular imports become likely.

   Fix: Use importlib lazy imports or restructure as packages.

   [MEDIUM] Service Initialization Order Dependency (main.py:236-265)
   ------------------------------------------------------------------
   Issue: Startup sequence is implicit. Queue processor MUST start before
          wearable sync, KB Growth MUST start after database init.

   Fix: Use dependency injection container for explicit ordering.

5. FRONTEND ISSUES
--------------------------------------------------------------------------------

   [HIGH] Large Component Files
   ----------------------------
   Diagnosis.tsx: 73,000 lines

   Impact: Unmaintainable, impossible to review, high bug risk.

   Fix: Split into subcomponents:
   - SymptomInput component
   - DiagnosisResults component
   - ICDCodeSelector component
   - TreatmentPlanner component
   - PatientHistory component

   [MEDIUM] No Error Boundaries (App.tsx)
   --------------------------------------
   Code:
       <Suspense fallback={routeFallback}>
         <Routes>
           {/* No error boundary wrapping routes */}
         </Routes>
       </Suspense>

   Impact: Single component error crashes entire app.

   Fix: Add React Error Boundary for graceful error handling.

   [LOW] Hardcoded API URLs
   ------------------------
   Issue: Some components may have hardcoded URLs instead of using
          VITE_API_BASE_URL environment variable.

   Fix: Audit all API calls, ensure consistent environment variable usage.

SHORT-TERM (Next Sprint)

   - lifespan.py (startup/shutdown)

2. Refactor Diagnosis.tsx - Extract subcomponents (target: <500 lines each)
3. Add unit tests for:

   - VoiceTranscriber.transcribe_audio()
   - HybridSearch.hybrid_search()
4. Implement email service for password reset (SendGrid/AWS SES)
5. Add request validation middleware (Pydantic models for all endpoints)

LONG-TERM (Architecture Roadmap)
--------------------------------------------------------------------------------
1. Service container - Use dependency injection framework
   (e.g., dependency-injector, FastAPI Depends)
2. Event-driven architecture - Replace background loops with event queue
   (Redis/RabbitMQ for reliable async processing)
3. API versioning - Add /api/v1/ prefix for future compatibility
4. Database migrations - Full Alembic setup instead of create_all()
5. OpenTelemetry - Distributed tracing across services
6. API Rate limiting - Implement per-user rate limiting
7. Audit logging - HIPAA-compliant audit trail for all patient data access
